Bruteforce Legacy iOS 2.2.1 — countdown timing and Mac device handling
Verification date: 2026-10-20

The third recovery log stops in stock DFU before the shared-image upload.
The old helper added USB query latency and interpreter startup to every tick.
The replacement uses monotonic phase deadlines and one nonblocking query.
Tests cover missing/slow queries, real blocked subprocess cleanup, early
detection, query failures, mismatched identity, and private-field redaction.

The passcode adapter had removed upstream's Mac device-agent suspension.
The replacement uses a detached lease watcher with exact per-user Apple paths,
start identities, and a cleanup journal. Live MacBook checks confirmed all
three agents paused and resumed after normal exit and forced parent death.
No phone firmware was sent during these checks. The original failing sequence
has not been reproduced with physical button input during this repair.

The dark GUI and hidden terminal/input defaults remain. Active progress clears
the stale response-waiting status. Final package tests and updater checks:
https://github.com/channelramble/Bruteforce-Legacy-iOS/releases/tag/v2.2.1

Bruteforce Legacy iOS 2.2.0 — dark GUI and 3G USB transition repair
Verification date: 2026-10-20

Reported failure and evidence:
  The second recovery log validates the correct n82 boot components and kernel,
  then stops at S5L8900 pwnDFU verification after the shared WTF upload.
  The old check waited two seconds and queried signature fields separately.
  A later read-only irecovery query on the connected phone returned iPhone1,2,
  n82ap, CPID 0x8900, BDID 0x04, MODE DFU, SRTG iBoot-596.24 (stock DFU).
  That snapshot supports the entry-mode diagnosis; it cannot establish the
  exact state during the earlier failed upload. No recovery boot was performed
  during this repair. No unique phone identifiers or raw user logs are included.

Corrections:
  Download and patch the shared component before timed button instructions.
  Distinguish WTF entry from stock DFU. Poll through re-enumeration and require
  the expected patched SRTG plus chip/board identity before board-specific iBSS.
  Already verified patched DFU is reused. Wrong boards, stale PWND strings,
  failed queries and uploads stop the workflow. Timeout diagnostics include
  only mode/chip/board/signature fields.
  The desktop uses a dark palette for pages, dialogs and native controls.
  Structured session events expose pauses, choices, passwords, DFU directions,
  countdowns, progress and bounded result cards. Timer review and errors do not
  depend on reading a terminal. Backend menu hooks preserve numeric choices;
  the timer path uses old-menu to avoid ANSI cursor-position queries.
  Terminal and manual input are separate opt-ins, both off on app launch.
  Failures never open the terminal automatically. Save log remains available.
  Typed responses are not logged by the app; secret echo is redacted across
  output chunks. Backend-reported results can still appear in exported logs.
  Prompt IDs reject stale/duplicate replies in the worker and GUI callbacks.
  The protocol flag is forwarded to WSL. Existing CLI interaction is retained.
  Desktop child interpreters inherit bytecode suppression so recovery helpers
  do not add cache files inside the signed app bundle.

Validation and limits:
  Tests include pinned backend shell execution with simulated USB modes,
  delayed enumeration, identity changes, upload failures and pre-iBSS checks.
  Real POSIX PTY fixtures exercise Continue -> select -> password -> result and
  graceful interruption. ConPTY and WSL adapters use mocked host fixtures.
  GUI tests cover hidden terminal/input defaults, password forms, choices,
  result persistence, cancellation, timer review gates and stale buttons.
  All six pages and active forms were rendered at 940x680 and 1120x800 without
  horizontal overflow, including long menus with Advanced terminal open.
  Intel deployment target remains macOS 12.0; ARMv6 payloads and desktop
  runtime inputs are unchanged. Native Windows/Linux USB, physical recovery,
  timer clearance and execution on actual Intel Monterey remain unverified.
  Final package checks, test totals, updater results and CI status:
  https://github.com/channelramble/Bruteforce-Legacy-iOS/releases/tag/v2.2.0

Bruteforce Legacy iOS 2.1.0 — guided desktop workflow
Verification date: 2026-10-20

Interface changes:
  A shared model and USB selector replaces selection duplicated across tasks.
  Start offers timer reset for a known passcode and recovery for a forgotten one.
  Timer reset follows Prepare -> Review & reset -> Done with one primary action
  per step. Applying changes still requires explicit confirmation. Changing the
  selected phone or its settings invalidates the prior review.
  Optional firmware, custom tools, and connection settings are under Advanced.
  Activity starts collapsed and opens for operations or errors. Progress and
  completion messages identify the operation; a recovery session ending is not
  presented as proof that a passcode was recovered.
  Phone and settings controls are locked while an operation is running.

Scope and verification status:
  This release changes the desktop interface and workflow. Recovery backend
  behavior, firmware profiles, ARMv6 payloads, and desktop runtime inputs remain
  unchanged. Intel Mac, Apple Silicon Mac, Windows x64, and Linux x64 archives
  are the intended release targets.
  224 tests passed in the development desktop environment. Python 3.9 ran the
  same suite with 22 GUI-dependent skips and no failures. The tests exercise
  guided timer state, stale selection invalidation, busy controls, cancellation,
  update eligibility and errors, backup gating, and transcript preservation.
  All six screens were rendered at 940x680 and 1120x800 with no horizontal
  overflow. The review action stays visible with Activity open at both sizes.
  Final results, exact test totals, package checks, updater results, and CI status:
  https://github.com/channelramble/Bruteforce-Legacy-iOS/releases/tag/v2.1.0
  Physical iPhone boot, timer reset, and passcode recovery remain unverified.
  Earlier verification records below do not establish current-release UI or
  package results.

Bruteforce Legacy iOS 2.0.1 — Intel Monterey and bundled 3G tools
Verification date: 2026-10-20

Mac compatibility:
  Intel x86-64 targets macOS 12.0 Monterey; Apple Silicon stays at macOS 14.0.
  Both Mac targets include Python 3.13.16 and Qt/PySide6/Shiboken 6.9.3.
  Intel uses cryptography 48.0.1; the other targets retain 50.0.2.
  The builder validates every loadable Mach-O image's selected architecture,
  declared deployment version, and hardcoded dylib dependency locations.
  Unused Qt SQL driver plugins with external database dependencies are omitted.
  Initial Intel development package: 225 native binaries checked, with a
  maximum declared deployment target of macOS 12.0.0.
  The included interpreter and six-page GUI self-test passed under Rosetta
  on the MacBook running macOS 27. This is not a Monterey execution test.
  Actual Intel Monterey hardware has not been tested.

  A retrospective v2.0.0 audit found 29 Qt/PySide/Shiboken images declaring
  macOS 26.0, another 203 Qt images declaring 14.4, and three optional SQL
  plugins linked to external database libraries. Its historical macOS 14+
  label did not match all bundled binaries. The v2.0.1 dependency selection
  and mandatory native-binary checks address that packaging problem.

iPhone 3G ARMv6 payload checks:
  Source: nabla-c0d3/iphone-dataprotection
  Revision: 572dd5cd8c07f5f14f7ea9488041031dd22a26bb
  Tools: bruteforce, device_infos, restored_external.
  A documented source patch removes automatic filesystem-repair calls and adds
  a bounded native wait mode before device initialization. Original source
  copies and the patch accompany the modified sources.
  Built for ARMv6 with the iPhoneOS 4.2 SDK and a true iOS 4.0 minimum target.
  Two builds produced identical executables.
  All imports in all three tools resolved against the actual 4.2.1 ramdisk.
  The bundled ZIP preserves SHA-1 and SHA-256 code signatures and avoids
  host macOS signing rewriting the on-device executables.
  The app verifies hashes before automatic extraction into a private
  per-operation temporary directory; no separate tools folder is required.
  Complete sources, rebuild recipe, provenance, notices, and license terms
  accompany the payloads in the app and source distribution.

3G firmware profiles:
  Passcode recovery: 4.2.1 / 8C148 ramdisk and matching kernel. Kernel input
  hash and all seven expected patch patterns must match before patching.
  Both iBSS and iBEC require exact original and patched hashes, and both get
  explicit RAM-disk boot arguments without nand-enable-reformat.
  Managed startup skips the upstream read/write mount script. The recovery
  executable mounts data read-only. Required ramdisk mutations and uploads
  stop on failure; stock restore startup cannot be used after a failed edit.
  Timer reset: separate Legacy iOS Kit 3.1.3 / 7E18 boot profile, retaining
  local IPSW validation. These boot profiles do not downgrade installed iOS.

  The complete adapted create_sshrd preparation pipeline passed offline with
  cached Apple components and real firmware tools. Extracted output contained
  the exact three payloads, managed startup, and separate wait helper, all 0755.
  iBSS, iBEC, and kernel roundtrips matched their validated profiles; the decoded
  DeviceTree parsed successfully. Every managed shell command was available.
  Exact hashes, modes, and command checks are recorded in
  docs/iphone3g-offline-verification.json. This was a host preparation test;
  no phone was accessed, booted, or modified during this check.

Remaining limits:
  No physical DFU boot, firmware boot, mount, timer clearance, or passcode
  recovery has been validated on an iPhone. Import and architecture checks
  do not establish working on-device behavior.
  Native Windows/ConPTY execution and WSL USB passthrough remain unverified.
  macOS signing is ad-hoc, without Developer ID signing or notarization.
  Windows binaries are not Authenticode signed.
  USB drivers, WSL, and external backend system tools remain host requirements.
  Final package checks, exact test totals, and release-specific CI results:
  https://github.com/channelramble/Bruteforce-Legacy-iOS/releases/tag/v2.0.1
