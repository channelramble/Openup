Regression tests exercise an actual SSH/SFTP handshake with that signature,
changed-host-key rejection, modern signature preference and unchanged globals.

using the unmodified hfs_mount_args header from pinned XNU 1504.9.37. It retains
ownership/encoding/timezone, skips a writable root, and checks the final flags.

checks validate architecture, iOS 4.0/SDK 4.2 deployment commands, LC_UNIXTHREAD,
SHA1/SHA256 code signatures and all imports against actual 4.2.1 ramdisk libraries
(127, 124 and 157 strong imports). All 330 tests pass, including the exact root
helper compiled with stubbed Darwin filesystem calls to test wrong-root,
already-writable, failed-update and ineffective-update paths.

check did not account for XNU initially naming the root root_device; returning
from the diagnostic allowed launchctl to continue into its normal bootstrap
with missing-directory warnings. The corrected helper verifies the actual root
device number against stat(/dev/md0), requires a block device, and accepts the
placeholder label. A fresh physical boot of the corrected binary established
authenticated SSH and SFTP again. Its exact SHA-256 was verified on the phone:
daff3018878a7e8112bbfc2fedcc9ab7027942940affa680757f89569209d5ea

usage error. The diagnostic holds on startup failure rather than falling

No passcode recovery or timer clearing was performed in these diagnostics.
The separate 3.1.3 timer route was not physically revalidated. Native Windows,
